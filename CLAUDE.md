# Shift-9 Studio — Operating Manual for Claude

This repo is `shift9-studio/.github`. It is three products in one repository:

1. **`profile/`** — the generated GitHub org page. `profile/README.md` renders live at
   github.com/shift9-studio. Its panels are images **generated by scripts**
   (`profile/scripts/build-panels.py`, `build-banner-photo.py`) — never hand-edit the
   SVG/PNG outputs in `profile/assets/`.
2. **`shift9/`** — pnpm + Turborepo monorepo (Node ≥ 20, pnpm ≥ 10, Next.js 16 App
   Router, Tailwind v4). Packages: `@shift9/theme` (tokens — single source of truth),
   `@shift9/ui`, `@shift9/motion`, `@shift9/data` (read-only Supabase). Apps:
   `apps/shift9-dev` (cyber-brutalist studio site → shift9.dev) and
   `apps/just-a-pinch` (warm food-forward product site → pinch.shift9.dev). Both
   deploy on Vercel from this repo; see `shift9/DEPLOY.md`.
3. **`docs/BLUEPRINT.md`** — the locked creative direction ("INSTRUMENT" system).
   Read it before any design-affecting change. It wins ties.

## Conventions (follow all of these)

### Design system
- **Tokens only.** Colors, type scale, spacing, springs come from `@shift9/theme`
  (`tokens.css` / `theme.css`). Never hardcode a hex, duration, or easing in an app
  or component. If a value doesn't exist as a token, add the token first, then use it.
  Canonical palette: Void `#0f172a`/`#0a0e1a`, Signal `#22d3ee`, Pulse `#8b5cf6`.
- **Two voices, never mixed.** `shift9-dev` is cyber-brutalist: mono labels, `//`
  asides, coordinate frames. `just-a-pinch` is warm and appetite-driven: **no** `//`
  labels, no techy chrome, warm accent palette. History has already had to strip
  leaked `//` labels out of Pinch once (commit 993b09e) — don't reintroduce them.
- **Copy is plain and concrete.** Say what a thing is and does; no marketing
  superlatives ("blazing-fast", "world-class", "revolutionary"). Commit fe776e3 is
  the precedent. Witty is allowed only inside `MonoLabel` microcopy on shift9-dev.

### Motion & accessibility (non-negotiable contract)
- Every animated component branches on `useReducedMotionSafe()` (from
  `@shift9/motion`) or `motion-safe:` and degrades to a **fully legible static
  state** — not a paused half-state.
- Decorative visuals (DitherField, scramble text, particles) are `aria-hidden` with
  the real string as the accessible name. SSR renders final text — no hydration
  mismatch, no layout shift (see `DecodeText.tsx` for the reference pattern).
- rAF-smoothed MotionValues, never per-event handlers, for pointer-driven effects.
- 3D/skew/proximity effects are **desktop-only** (pointer: fine / min-width gate).
  Mobile gets the flat layout. WorkWall already regressed on mobile once (892a93e).

### Data
- `@shift9/data` is the only place Supabase is touched. The client is public,
  read-only, RLS-protected, and returns `null` when env vars are missing — every
  consumer **must** have a static fallback so pages never fail to render or build.
  Never introduce a service-role key anywhere in this repo.

### Git / PRs
- All work on the designated `claude/...` feature branch. Never push to `main`.
- One PR per coherent change; descriptive title in the style of the existing log
  (`fix(motion): …`, `content: …`, or a plain sentence). Push, open a ready PR,
  don't merge without user approval.
- Commit generated profile assets together with the script change that produced them.

### Higgsfield / AI generation
- **Never generate without an explicit request in this turn.**
- **One job per asset, no duplicates.** Never launch a backup/fallback workflow while
  one is running or before checking whether the first succeeded.
- **Test one, then fan out.** New model or prompt style → single test job → confirm
  a valid result → then the full set.
- **One generation workflow at a time.** Fan out *within* a workflow, never two
  parallel workflows calling generate_* for the same list.
- **No auto-retry.** A failed job is reported, not silently resubmitted.

### General
- Never run the same agent task twice in parallel; if two workflows would do the
  same work, run one and wait.

## Named failure modes → the rule that prevents each

| Mistake a weaker model will make | Rule |
|---|---|
| Hand-edits `profile/assets/*.svg`/`.png` to change profile copy | Edit `profile/scripts/build-panels.py` (copy lives in the script), rerun it, commit script + regenerated assets together. |
| Changes profile panel text but not the `alt` text in `profile/README.md` | Every panel image's `alt` must restate its full visible text; update both in the same commit. |
| Puts a hex color / magic duration in a component | Use or add a token in `@shift9/theme`. Grep your diff for `#[0-9a-f]{6}` and raw `ms` values before committing. |
| Adds motion with no reduced-motion branch | No `animate`/`transition`/rAF loop without a `useReducedMotionSafe()` (or `motion-safe:`) branch to a static state. |
| Ships a cursor/3D effect that breaks phones | Gate skew/proximity/magnetic effects behind desktop media/pointer checks; verify the flat mobile fallback exists. |
| Bleeds cyber styling (mono `//` labels, Signal cyan chrome) into Just a Pinch | Before touching `apps/just-a-pinch`, re-read its `globals.css` + existing components; Pinch never uses `//` labels. |
| Makes a page throw when Supabase env vars are absent | Every `getSupabase()` consumer handles `null` with static content; both apps must `next build` with **no** env vars set. |
| "Fixes" fonts/animation in GitHub README with CSS or JS | GitHub strips `<style>` in markdown and animates SVG inconsistently (mobile serves PNG for a reason, d76e670). Only SMIL-in-SVG for desktop assets + static PNG fallbacks work. |
| Runs `npm install` / adds a lockfile at repo root | The workspace root is `shift9/`; use `pnpm` there. `node-linker=hoisted` is intentional — don't change `.npmrc`. |
| Submits duplicate or retry Higgsfield jobs | The five generation rules above; when in doubt, `show_generations`/job status first, generate never. |
| Merges its own PR or pushes to `main` | PRs are opened ready-for-review and left for the user. |

## Quality bar per deliverable (checkable, all must pass)

**Any code change in `shift9/`:**
- [ ] `pnpm --filter shift9-dev build` and `pnpm --filter just-a-pinch build` exit 0
  (run from `shift9/`), with no new warnings you introduced.
- [ ] `pnpm typecheck` passes; no new `any`, no `@ts-ignore`/`@ts-expect-error`.
- [ ] Diff contains zero raw hex colors, zero raw timing values (tokens only).
- [ ] Both apps build with no `.env` present (static-fallback proof).
- [ ] New components: `"use client"` only if actually needed; SSR output equals
  final visual state (no hydration mismatch / CLS).

**Any motion/visual change:**
- [ ] Reduced-motion path exists and renders complete, readable content.
- [ ] Decorative layers `aria-hidden`; interactive elements keep visible
  `:focus-visible`.
- [ ] Verified (or reasoned explicitly in the PR body) at 375px width and desktop;
  transforms gated off mobile.

**Profile page changes:**
- [ ] Regenerated via the script; script diff and asset diff in the same commit.
- [ ] Every `<img>` has `alt` matching its rendered text verbatim.
- [ ] Panels use only baked-in SVG/PNG (no external fonts, no CSS, no JS).
- [ ] Links point at live destinations (shift9.dev, pinch.shift9.dev, real repos) —
  no placeholder or dead URLs (precedent: 442e013).

**Copy changes (any surface):**
- [ ] Concrete noun + what it does; no unverifiable superlatives.
- [ ] Voice matches the surface (cyber for shift9-dev/profile, warm for Pinch).

**PRs:**
- [ ] Title in the repo's existing style; body states what changed, why, and which
  checklist items above were verified (and how).
- [ ] Branch is `claude/...`; PR is ready-for-review, not draft, not merged.

## When uncertain — exact escalation rules

Proceed **without asking** when: the change is reversible, on the feature branch,
inside the scope of the request, and every ambiguity has one reading consistent
with the blueprint and this file. State the assumption you made in the PR body.

**Stop and ask (AskUserQuestion / report and wait)** when any of these is true:
1. The change would alter locked creative direction (palette, INSTRUMENT concepts,
   brand voice, surface separation) — blueprint §0 is user-only territory.
2. Anything touching money or external quota: Higgsfield credits beyond an
   explicitly requested set, new paid services, domain/DNS, Vercel project settings.
3. Any destructive or hard-to-reverse action: force-push, deleting assets, rewriting
   `main` history, Supabase schema/policy changes (this repo is read-only toward
   Supabase — schema work is out of scope entirely unless the user says otherwise).
4. A generation job failed → report the failure and the proposed resubmission; never
   resubmit on your own.
5. A reviewer comment or instruction has two materially different readings, or a fix
   requires refactoring beyond the files the task named.
6. Two of this file's rules conflict, or following the request would violate one —
   name the conflict instead of silently picking.

If blocked mid-task by a failing build you cannot attribute to your own diff:
verify against a clean checkout of the base branch first; if it fails there too,
report it as pre-existing and continue only with your scoped change.

## Execution environment — capability map (READ THIS BEFORE FIGHTING A WALL)

This repo runs in a sandboxed remote environment with a policy proxy. The walls
below are **fixed** — retrying the blocked call is wasted effort. For each, the
**working path is already known**; take it the first time. Do not rediscover
these by trial and error every session.

| You need to… | ❌ Blocked path (don't retry) | ✅ Working path (do this) |
|---|---|---|
| **Read another owner's / out-of-scope repo** (e.g. `Kariimc/*`) | `add_repo` → "cross-tier not supported"; github MCP / REST → 403 "not configured for this session" | `git clone https://github.com/<owner>/<repo>` — the env rewrites `github.com` → an internal git proxy that serves **any** repo read-only. Clone into the scratchpad, don't commit it. |
| **Run another repo's app / capture real screens** | asking the user for screenshots | Clone it (above), install, run headless. RN/Expo apps: `expo start --web` (they're web-aware) → drive with the pre-installed Chromium (`/opt/pw-browsers/...`) + `playwright-core`. |
| **Change GitHub repo/org *settings*** — rename, archive, description, topics, pins, org metadata, website | REST API (`PATCH /repos/...`, `/orgs/...`) → **403**. The session token is a GitHub **App installation token scoped to `shift9-studio/.github` only** (empty OAuth scopes). Git push to other repos is also 403. | **Owner-only.** These are metadata, not git — no file/branch performs them. Do them in a session whose token has admin on the target repos/org, or hand the user the one-click Settings steps. Record it and move on; never loop on the API. |
| **Supabase DB work** (schema, insert, verify a row) | direct HTTPS to `*.supabase.co` from the sandbox → "Host not in allowlist" (works fine on Vercel at runtime) | Use the **Supabase MCP** (`apply_migration`, `execute_sql`). App code that hits Supabase over HTTP will 500 in the sandbox but works in production — verify the DB path via MCP, not a local round-trip. |
| **Fetch a file from an arbitrary host** (e.g. a paste/temp host) | `curl`/`wget`/WebFetch → 403 CONNECT (egress policy) | Have the user upload it (arrives under `/root/.claude/uploads/…`), or host it on an allowlisted service (GitHub, Drive). Never re-curl a host that already 403'd. |
| **npm/pnpm/pip installs, `github.com` git, `api.github.com` reads** | — | Allowed. These work normally. |

Rule of thumb: **git works for any repo (read); REST admin works for nothing beyond `shift9-studio/.github`; HTTP egress is allowlist-only.** If a call is blocked, switch primitive (usually to git or an MCP) — do not repeat it.

## Operating failures to never repeat (learned the hard way)

These cost a real session ~7 wasted hours on ~2 hours of work. They are behavioural,
not technical. Do not repeat them.

1. **A blocked call is not a blocked task.** When something fails (download, API,
   `add_repo`), switch primitive *immediately* — try `git clone`, an MCP, an upload —
   before you ever say "blocked". Exhaust the capability map above first. Never retry
   the identical failing call hoping for a different result.
2. **Never hand the user legwork.** Don't ask them to fetch a file, flip a setting,
   or run a command you could do another way. Investigate with tools instead of
   assigning tasks. At most one irreducible manual step, stated in one plain line —
   and only when it is genuinely the only path.
3. **Finish the request — including the last step.** "Build it and merge it" means
   merge it once approved, not leave PRs sitting while you announce they're "ready."
   If a human click is the only way, say so in one plain sentence up front and offer
   to do it — don't let work stall unmerged without the user understanding why.
4. **Plain language, no plumbing.** State the outcome and the single next action.
   Do not paste tool mechanics, proxy internals, or walls of hedged text. If the user
   says "be concise / stop the jargon", that is binding immediately — not a suggestion.
5. **Explain consequences before the fact.** The first time PRs exist, say plainly:
   *preview deploys are per-branch and disposable; nothing touches the live site until
   it merges to `main`.* Don't let the user discover how the workflow works by being
   confused by it.
6. **Don't stall or over-ask.** Proceed on anything reversible and in-scope; batch the
   genuinely blocking questions into one round and keep moving. Momentum on the work
   beats a tidy list of things for the user to decide.
